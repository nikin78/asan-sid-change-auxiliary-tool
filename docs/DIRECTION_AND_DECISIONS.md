# 방향 전환 및 결정 사항 기록 (SID 변경 사전·사후 보조 툴)

> 기록일: 2026-11-25
> 상태: **계획 확정, 코드 작업은 아직 시작 전.** 다음 작업은 아래 "단계별 실행 계획"의 1단계부터 진행합니다.
> 기존 인수인계서: [HANDOVER.md](../HANDOVER.md) (기존 USB 부팅 도우미 사양 및 6대 절대 제약사항 — 계속 유효)

---

## 1. 새 방향성 (사용자 요구)

기존 `USB_Reboot.bat`(UEFI USB 일회성 부팅 도우미 + 다중 디스크 EFI 충돌 방지)을 확장해서,
**WinPE USB 부팅 환경에서 진행하는 C드라이브 Windows SID 변경 작업을 사전·사후로 보조하는 툴**로 만듭니다.

* **사전(Pre-SID):** WinPE 부팅 전,
  1. C드라이브(현재 OS) 외 다른 내장 드라이브에 남아 있는 EFI 부트로더를 탐지하고 무력화 (예상치 못한 부팅 오류 사전 제거)
  2. 그 다음 USB 부팅 디스크를 골라 자동 재부팅
* **사후(Post-SID):** SID 변경 후, 골든 이미지 복제본이라 SID 중복을 피하려고 SID를 바꾼 PC에서
  메인 프린터 PC가 호스팅하는 공유 프린터를 쓸 수 없는 문제를 **프린터 스풀러 리셋**으로 해결

---

## 2. 사용자 답변 원문 (질문 1~5에 대한 답)

1. 복제 후 PC 부팅 및 기본 설정 마친 상태에서 문제 발생할 때 별도 WinPE 및 관련 부처에서 직접 개발한 SID 변경 툴을 이용해 WinPE 환경에서 SID를 변경하는 거야. 일단 현장에선 SID 작업을 마치면 공유 폴더의 경우 다른 PC에서 원활히 접속이 가능해지기 시작하고, 공유 프린터의 경우, SID 작업이 끝난 메인 PC, 그리고 클라이언트 PC 각각에서 프린터 스풀러를 한 차레 비워줘야 정상 연결 및 이용이 가능해지더라. 리셋 수준은 이에 맞추어 네가 적절히 선택 및 적용해줘.
2. 사전 작업은 결국 SID 변경을 위한 WinPE 부팅 전, USB 부팅 디스크 선택 및 자동 부팅 툴 기능과, 다른 드라이브 잔존 부트로더 탐지 및 사전 제거 두 가지를 통합하여 제공하기 위함이야. 물론 후자에서 USB 부팅 디스크의 부트로더까지 제거해버리는 문제가 발생하면 안 되겠지. 첫 화면 구성은 그렇기에 UI에서 [2]는 그대로 하되, [1]. [3]은 한 화면에서 제공하는 방향으로 통합해서 주는 게 좋지 않을까 싶은데. 사전 작업에서 (PC 장착된 C 외 타 드라이브의) 잔존 부트 로더 탐지 및 제거가 반드시 선행되어야 하고, 그 다음에 USB 부팅이 사용자 선택에 따라 이루어 질 수 있도록 UX를 설계했으면 하네.
3. ㅇㅇ 역할에 맞게 바꾸어줘.
4. 대부분 GPT EFI 파티션이긴 할 텐데... 만약 네 소견상 구형 MBR 활성 부팅 파티션 또한 (C드라이브의 UEFI 환경에서 조차) 내가 겪었던 부트로더 문제를 야기할 수 있다고 판단되면 그 땐 적극 고려해줘.
5. SID 작업한 PC가 곧 공유 프린터를 호스팅하는 메인 프린터 PC일텐데, 이걸 테스트 할 필요가 있나...? 있다고 하는 요소가 있으면 반영하여서 관련 정보를 모두 디스플레이하되, 어디까지나 스풀러 리셋에 초점을 맞추어주었으면 하네.

## 3. 답변을 반영한 설계 결정

### 3.1 메인 화면 (정상 Windows)
```
[1] SID 변경 사전 작업   (잔존 부트로더 탐지·제거  →  USB 부팅)
[2] SID 변경 사후 작업   (프린터 스풀러 리셋)
[Q] 종료
```
* 기존 계획의 `[1] 사전 작업`과 `[3] 내장 EFI 관리`를 **한 화면(사전 작업)으로 통합**.
* WinPE(`X:`)에서 실행하면 지금처럼 **WinPE 비상 모드**(EFI ↔ EFI_OLD 수동 복구)로 바로 진입.
* UEFI 필수 검사는 사전 작업 안으로 이동 → 사후 작업은 USB 없이도, Legacy PC에서도 실행 가능.

### 3.2 사전 작업 UX: "부트로더 정리 선행 → USB 부팅" 순서 강제
* **STEP 1 (필수 선행):** C드라이브 외 내장 디스크의 잔존 부트로더 탐지 결과를 먼저 표시.
  * 위험 발견 시 기본 동작은 "무력화(EFI → EFI_OLD)". STEP 1을 해결하거나, 위험을 이해했다는
    명시적 확인(예: 문구 입력)을 하기 전에는 STEP 2로 넘어갈 수 없게 함.
  * 위험이 없으면 "정상" 표시 후 바로 STEP 2 진행 가능.
* **STEP 2 (사용자 선택):** BIOS 차단 요소 확인 → USB 목록·NVRAM 매칭 → 사용자 확인 후 일회성 재부팅.
* **USB 부팅 디스크 보호:** USB/외장 디스크(`BusType=USB`, Removable, `USBSTOR/UASP`)는 부트로더 탐지·제거 대상에서
  원천 제외. 추가로 WinPE 매체 표식(`sources\boot.wim`, `EFI\BOOT\BOOTX64.EFI`만 있고 Microsoft 폴더 없음 등)이
  보이는 파티션은 내장 디스크라도 자동 차단(외장 NVMe 인클로저가 내장처럼 보이는 경우 대비).
  기존 코드에 누락된 `sources\boot.wim` 가드도 이때 추가.

### 3.3 구형 MBR 활성 부팅 파티션 (질문 4 소견)
* **판단:** UEFI 순수 모드(CSM/Legacy 꺼짐)에서는 펌웨어가 MBR 부트코드를 실행하지 않으므로 직접 원인은 아님.
  하지만 **CSM(Legacy 호환)이 켜진 보드**(구형 삼성/HP/Dell에서 흔함)에서는 SID 작업 후 NVRAM 부팅 항목이
  흔들리거나 BIOS 기본값 복원 시 보조 HDD의 MBR 활성 파티션(`bootmgr` + `\Boot\BCD`)으로 부팅이 넘어가
  구형 Windows 부팅/자동 복구 진입이 발생할 수 있음 → **고려 대상에 포함.**
* **적용 방침:** 보조 MBR 디스크에서 활성(Active) 파티션 + `bootmgr`/`\Boot\BCD` 존재 시 "충돌 위험"으로 표시.
  조치는 비파괴·즉시 복구 가능한 방식만 사용(파티션 삭제/포맷 금지 원칙 유지):
  `bootmgr` → `bootmgr_OLD`, `Boot` → `Boot_OLD` 이름 변경 (필요 시 `diskpart inactive` 병행 여부는 구현 단계에서 확정).
* 현재 PC의 CSM 상태는 WMI로 대부분 읽을 수 없으므로 "확인 불가" 원칙 유지.

### 3.4 사후 작업: 프린터 스풀러 리셋 (질문 1, 5)
* **현장 사실:** SID 변경 후 공유 폴더는 바로 정상화되지만, 공유 프린터는 **메인(호스트) PC와 각 클라이언트 PC 모두에서**
  스풀러를 한 번 비워야 정상 연결됨.
* **리셋 수준 결정 (기본 리셋 + 안전 보강):**
  1. `Spooler` 서비스 중지 (의존 서비스 포함, 타임아웃 시 프로세스 정리)
  2. `%SystemRoot%\System32\spool\PRINTERS\*` (`.SPL`/`.SHD` 대기열 파일) 비우기
  3. `Spooler` 재시작 + 시작 유형이 `Disabled`면 `Automatic`으로 복구
  4. 결과 리포트
  * 기존 프린터·드라이버·공유 설정은 **삭제하지 않음**. (더 강한 리셋은 현장에서 기본 리셋으로 해결되지 않을 때만 별도 옵션으로 검토)
* **같은 도구로 호스트/클라이언트 모두 처리:** 실행한 PC가 공유 프린터를 가진 경우 `[호스트(메인 프린터 PC)]`, 아니면
  `[클라이언트]`로 자동 표시. 화면 안내: "메인 PC와 클라이언트 PC 각각에서 한 번씩 실행하세요."
* **표시할 정보 (테스트 대신 상태 표시, 스풀러 리셋이 주 기능):**
  * 공통: 컴퓨터 이름, 현재 Machine SID(참고용), `Spooler` 상태/시작 유형, 대기열 파일 수, 설치된 프린터 목록
  * 호스트: 공유 중인 프린터 목록(공유 이름), "파일 및 프린터 공유" 방화벽 규칙 상태, 네트워크 프로필(공용이면 경고)
  * 클라이언트: 연결된 네트워크 프린터(`\\서버\프린터`)와 대상 PC 응답 여부(간단 확인)
  * 메인 PC 자신에 대한 연결 테스트는 의미가 없으므로 하지 않음.

### 3.5 파일명
* 배포 파일명을 역할에 맞게 변경: `USB_Reboot.bat` → **`SID_Change_Aux_Tool.bat`** (구현 1~2단계에서 적용)
* `modules/`에서 기능별로 관리하고, 개발용 빌드 스크립트로 단일 배포 `.bat`을 생성·검증 (배포물은 계속 `.bat` 1개).

## 4. 단계별 실행 계획 (각 단계 끝에서 테스트)

| 단계 | 내용 | 테스트 방법 |
|---|---|---|
| 1 | 빌드/검증 스크립트(ASCII·CRLF·문법) + 기존 결함 수정(`boot.wim` 가드, 한글 `bcdedit` 인코딩, Gate 0 취소 흐름) + 파일명 변경 | 빌드 검증 통과, `[D]`/`[L]` 진단 정상 출력 |
| 2 | 메인 화면 `[1]` 사전 / `[2]` 사후 구조 + 사전 작업 STEP 1 → STEP 2 순서 강제 UX | 메뉴 분기·복귀, 기존 USB 부팅 흐름 회귀 테스트 |
| 3 | 사후 작업: 프린터 스풀러 리셋 모듈 + 호스트/클라이언트 상태 표시 | 메인 PC·클라이언트 PC 각각 실행 후 공유 프린터 인쇄 확인 |
| 4 | 사전 작업 보강: USB/WinPE 매체 보호 강화, MBR 활성 파티션 탐지·무력화, WinPE `diskpart` 폴백 | 다중 디스크 PC, 실제 WinPE 부팅에서 탐지·전환 |
| 5 | 실장비 검증 (Samsung S8, HP G9, Dell DCM 유/무) 및 튜닝 | 제조사별 체크리스트 |
| 6 | `HANDOVER.md` 갱신 및 최종 배포 검증 | 최종 `.bat` 단독 실행 확인 |
